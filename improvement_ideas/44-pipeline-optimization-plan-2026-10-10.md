# Pipeline optimization plan — 2026-10-10

This plan consolidates the source audit of twenty pipeline stages and the Gaussian/text-filter review. **No performance changes or benchmarks were implemented or run during this review.** Candidates below need measurement against OkuFlow's current implementation. There is no dependency or licensing change, and no claimed percentage speedup. The running application, camera, and GPU workload were left undisturbed.

Prioritize unnecessary work before replacing algorithms: first restrict Maxine resets to relevant configuration changes (audit U4), then gate unused text statistics and discarded sharpening. Profile the resulting pipeline before selecting kernel substitutions. Correctness fixes for light-polarity Sauvola, CLAHE boundaries, and independent glare/flatten controls belong to the accompanying audit; optimization must preserve their corrected behavior.

The pipeline operates at several cadences. Most CUDA effects process new camera frames; stabilization/keystone analyze smaller images; focus and keystone readback are sampled; D3D presents cached scenes at the display rate. Optimizing an inactive legacy path or multiplying camera work by presented FPS would misidentify the bottleneck.

## Blur: preserve the existing baseline

Gaussian blur is disabled by default; its stored defaults are radius 3, sigma 1. Current CPU and CUDA implementations already use two one-dimensional passes. A radius-3 kernel therefore uses **14 logical taps per output instead of a naive two-dimensional filter's 49**. This is the existing baseline, not a newly available gain. Logical taps are neither DRAM bytes nor elapsed time. [NVIDIA's filtering chapter](https://developer.nvidia.com/gpugems/gpugems2/part-iii-high-quality-rendering/chapter-27-advanced-high-quality-filtering) explains both separability and the overhead of additional passes.

CUDA coefficients are cached in constant memory and updated when radius/sigma changes. Work surfaces and shared scratch are reused. Moving exponentials out of the pixel loop or removing per-frame Gaussian allocations would duplicate existing work. CPU coefficient generation repeats, but that CPU effect path serves the legacy debug composite, so it is a lower shipping-performance priority.

Both implementations quantize the horizontal intermediate to eight bits. CPU rounds; CUDA truncates. Preserve that distinction when establishing a reference: the CPU implementation is not a byte-exact CUDA oracle. A floating intermediate or linear-light filtering is a quality change with different bandwidth costs.

Exact candidates include pruning coefficients that are already exactly zero without renormalizing, preserving arithmetic order while staging shared-memory halos, and specializing common radii. Small radii may favor today's cached global loads. Vertical reads are not universally uncoalesced: neighboring x threads access neighboring pixels. Compare variants instead of assuming shared memory wins. [NVIDIA's convolution examples](https://github.com/NVIDIA/cuda-samples/blob/master/cpp/2_Concepts_and_Techniques/README.md) provide implementation references for such comparisons.

Approximate candidates require a separate acceptance target. Truncating merely small Gaussian tails changes weights. Bilinear tap pairing matches weighted sums in ideal arithmetic, but hardware interpolation has finite precision and does not prove byte equality or halve physical traffic. Persistent texture bindings, correct centers, and clamp behavior are required. [CUDA texture filtering precision](https://docs.nvidia.com/cuda/archive/12.8.1/pdf/CUDA_C_Programming_Guide.pdf), §18.2.

Kawase and Dual Kawase use different responses; down/up sampling can introduce phase dependence, anisotropy, and shimmer. Evaluate them only for measured expensive visual softening, with an explicit sigma-to-pass schedule. The current sigma ceiling is 5, so broad-blur demonstrations do not establish an advantage here. They must not replace Sauvola statistics, tracking prefilters, bilateral denoising, or temporal averaging. [Intel's blur investigation](https://www.intel.com/content/www/us/en/developer/articles/technical/an-investigation-of-fast-real-time-gpu-based-image-blur-algorithms.html) and [Arm's original Dual Filtering presentation](https://developer.arm.com/cfs-file/__key/communityserver-blogs-components-weblogfiles/00-00-00-20-66/siggraph2015_2D00_mmg_2D00_marius_2D00_slides.pdf) motivate experiments, not OkuFlow speed claims.

The tracking pyramid does contain a direct 5×5 binomial filter, but only on small analysis levels. A separable decimating version needs a half-width, full-height horizontal intermediate before vertical decimation; simply counting two five-tap passes per final pixel undercounts its work. Extra launches/traffic may outweigh savings. Preserve phase, borders, odd dimensions, and tracking accuracy.

## Order of implementation and acceptance

1. Restrict Maxine resets, then build a dependency plan for text consumers. Focus-only requires sampled original luma; CLAHE-only and nonselective sharpening require no shared local moments; flatten/glare needs mean but not necessarily variance; masks need statistics from the correctly modified image. Remove only demonstrably unused work.
2. Add sparse stage timings and resource counters, then select the measured dominant copy, allocation, scan, or kernel. Existing effects timings aggregate several stages and exclude some queue waits. Do not add per-kernel host synchronizations to obtain timings.
3. Implement equivalent pass/memory reductions first. Evaluate Gaussian tiling, text scans, or pyramid restructuring only when their measured share warrants it. Keep approximate filters in separately reviewed experiments.

For later authorized validation, freeze current CUDA outputs and use independent double-precision mathematical references. Cover constants, impulses at center/edges, ramps, one-pixel strokes, low-contrast text, colored edges, noise, tiny/odd dimensions, padded pitches, portrait frames, and production resolutions. Include parameter extremes and meaningful text-feature combinations. Compare maximum/percentile byte error, mask disagreements, stroke contrast, and near-zero variance. Approximate filters additionally need subpixel text pans and slow parameter changes at magnified viewing sizes; static photograph PSNR is insufficient.

Measure warmed stage and whole-frame p50/p95 timings on the processing stream, and separate cold model loads/configuration spikes, allocation counts, queue delays, and UI responsiveness. Record GPU, toolchain, format, dimensions, and enabled settings. Use [Nsight Systems](https://docs.nvidia.com/nsight-systems/UserGuide/index.html) for scheduling and [Nsight Compute](https://docs.nvidia.com/nsight-compute/ProfilingGuide/index.html) for justified kernel investigations. Run the tracked CPU/CUDA validation matrix with implementation changes. Accept an optimization only when its measured end-to-end benefit and image/lifetime checks support it; this document alone establishes neither.
