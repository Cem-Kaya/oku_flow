## What "high-FPS async overlay" really achieves

Repaint is reprojection, not tracking. `OnPresented` runs before `PresentSceneTexture` ([app_pipeline_runtime.cpp](/C:/Users/USER/AppData/Local/OkuFlow/worktrees/test-opt/src/app/app_pipeline_runtime.cpp:1206) vs 1293) and calls `SetViewTransform`, which early-outs unless the transform changed ([overlay.cpp](/C:/Users/USER/AppData/Local/OkuFlow/worktrees/test-opt/src/ui/ultra_clear_text_overlay.cpp:85)). So pan/zoom/Fit-Fill/resize follow at presentation rate with zero OCR work — that part is real and well tested (`cachedGlyphsRepaintWhileRecognitionIsHeld` pans the transform 300× with a frozen validated frame).

Camera/page motion *inside* the scene does not change the transform. Glyphs then stay frozen over moving pixels until the next probe outcome (≥80 ms probe interval + readback + worker queue) updates the per-line translation `sceneOffset` in a step, or invalidates the line. Effective content tracking is therefore ≤12.5 Hz, translation-only, bounded to ±6 probe px, with a 350 ms freshness gate ([ultra_clear_text.cpp](/C:/Users/USER/AppData/Local/OkuFlow/worktrees/test-opt/src/common/ultra_clear_text.cpp:1410)). At 100 px/s hand motion that's 8–15 px of swim, then a snap. Rotation/scale/perspective drift is not tracked at all; NCC fails and text hides (correct fail-closed). Additionally, the Qt Tool overlay window composites through DWM independently of the D3D swapchain, and `OnPresented` fires *before* the present call, so one-frame glyph/video tear during fast pan is possible and unmeasured. No test moves page content while asserting glyph registration over time — `contentMotionHidesTextAndStaleProbeExpires` only asserts eventual hiding.

## Defects (independently reproducible)

**D1 — Blank plate erases original (P1).** Plate loop skips on OCR-box height <6 px ([overlay.cpp:322](/C:/Users/USER/AppData/Local/OkuFlow/worktrees/test-opt/src/ui/ultra_clear_text_overlay.cpp:322)); glyph loop skips on *ink* height <6 px or empty ink ([overlay.cpp:334](/C:/Users/USER/AppData/Local/OkuFlow/worktrees/test-opt/src/ui/ultra_clear_text_overlay.cpp:334)). Trigger at unit level without OCR: `SetWords` with text `"-"` (plain punctuation, passes `IsHighRiskToken`) in a box projecting to ≥6 px height in a normally-scaled line — ink height projects to ~1–2 px, glyph skipped, plate filled. Same when `tightBoundingRect` is empty (`glyphs_[i]={}` at [overlay.cpp:265](/C:/Users/USER/AppData/Local/OkuFlow/worktrees/test-opt/src/ui/ultra_clear_text_overlay.cpp:265)) — the plate loop never checks glyph validity. Fix: one shared draw predicate computed in `RebuildGlyphLayout`/projection; plate only if glyph will draw. Regression: offscreen `render()` of that word must produce zero plate pixels (fails today).

**D2 — Per-word anisotropic distortion (P1 quality).** Rendered ink width is forced to the OCR box width while height uses the line-median scale ([overlay.cpp:268](/C:/Users/USER/AppData/Local/OkuFlow/worktrees/test-opt/src/ui/ultra_clear_text_overlay.cpp:268), [overlay.cpp:339](/C:/Users/USER/AppData/Local/OkuFlow/worktrees/test-opt/src/ui/ultra_clear_text_overlay.cpp:339)), then `painter.scale(scaleX, scaleY)` with independent axes. Whenever the source typeface's advance differs from Segoe UI (most print), every word is horizontally squeezed/stretched by a different ratio — exactly the letterform damage low-vision readers are sensitive to. `glyphsShareLineBaselineDespiteDifferentInkHeights` asserts baseline/top/height only, never width or rendered pixels. Fix: uniform scale (`scaleX = line scaleY`), left-anchor at OCR box left; the plate already unions original and rendered ink ([overlay.cpp:327](/C:/Users/USER/AppData/Local/OkuFlow/worktrees/test-opt/src/ui/ultra_clear_text_overlay.cpp:327)). If box-fit must be kept, clamp aspect to ~0.9–1.1. Regression: word whose box is 1.6× Segoe ink width must render at uniform-scale width, not box width.

**D3 — Reading pane destroys caret/selection (P2, accessibility).** Header promises caret preservation ([ultra_clear_text_panel.hpp:32](/C:/Users/USER/AppData/Local/OkuFlow/worktrees/test-opt/include/okuflow/ui/ultra_clear_text_panel.hpp:32)) but `SetReadingText` calls `setPlainText` and restores only vertical scroll ([ultra_clear_text_panel.cpp:98](/C:/Users/USER/AppData/Local/OkuFlow/worktrees/test-opt/src/ui/ultra_clear_text_panel.cpp:98)). A screen-reader or keyboard user mid-read loses position whenever the shown set changes. Fix: preserve cursor anchor/position clamped, or defer replacement while the pane has focus. Regression: set cursor to offset 5, replace text, assert cursor still 5 (fails today, resets to 0).

**D4 — Color polarity by minority class (P2).** `MeasureLineColors` splits at mean luma and declares the minority class foreground ([ultra_clear_text.cpp:211](/C:/Users/USER/AppData/Local/OkuFlow/worktrees/test-opt/src/common/ultra_clear_text.cpp:211)). Bold/zoomed text covering >50% of a tight line box inverts plate/glyph colors; the 7:1 fallback in `ReadableColors` inherits the wrong polarity ([overlay.cpp:40](/C:/Users/USER/AppData/Local/OkuFlow/worktrees/test-opt/src/ui/ultra_clear_text_overlay.cpp:40)). Fix: sample the box border ring as background (text rarely touches all four borders), take foreground from the opposite luma extreme. Regression: synthetic line with 60% ink coverage must keep ink as foreground.

**D5 — Global OCR polarity decision (P2).** Inversion is decided by whole-frame mean luma <110 ([uct_default_recognizer.cpp:63](/C:/Users/USER/AppData/Local/OkuFlow/worktrees/test-opt/src/common/uct_default_recognizer.cpp:63)). White-on-blackboard text in a bright room, or a dark page in a dim room, flips the wrong way and OCR silently yields nothing/garbage (then temporal agreement can still accept repeated garbage). Fix: if the first pass returns zero/few lines, retry inverted on the same worker job — bounded 2× worker cost, no UI impact. Regression: fixture page, light text on dark board occupying the centre third with bright surround, must recognize (fails today by construction of the mean).

**D6 — Omission ellipsis always trails the line (P3).** `ReadingText` appends one `…` at line end regardless of which/how many words were omitted ([ultra_clear_text.cpp:1506](/C:/Users/USER/AppData/Local/OkuFlow/worktrees/test-opt/src/common/ultra_clear_text.cpp:1506)); omission position is discarded at admission (count only). `Total is 3.14 and … ok` reads as `Total is 3.14 and ok …`, mislocating the gap the panel description claims to mark. The existing test encodes the trailing behaviour (`endsWith("…")`), so this is a deliberate-expectation change: store omitted placeholders in word order. Regression: middle high-risk word → `alpha … gamma`.

**D7 — Glyph weight unreachable for UCT-only users (P3 usability).** Weight comes from the Stroke weight slider inside Fine-tune, whose content is disabled unless optical Text Clarity is on ([main_window.cpp:2732](/C:/Users/USER/AppData/Local/OkuFlow/worktrees/test-opt/src/ui/main_window.cpp:2732)); the UCT panel itself sits outside that group ([main_window.cpp:978](/C:/Users/USER/AppData/Local/OkuFlow/worktrees/test-opt/src/ui/main_window.cpp:978)). Users must enable an unrelated pixel pipeline (which also changes OCR input) to thicken glyphs. Smallest fix: duplicate no UI — enable just that slider row when UCT is checked, or move the slider out of the dependent group.

**D8 — Static panel strings bypass translation routing (P3, doc/code mismatch).** `docs/localization.md` states UCT controls use `TranslateUi` routing, but checkbox/pane/accessible strings are raw `QStringLiteral` set once in the ctor ([ultra_clear_text_panel.cpp:24](/C:/Users/USER/AppData/Local/OkuFlow/worktrees/test-opt/src/ui/ultra_clear_text_panel.cpp:24)); only status goes through live-text. Even after catalog entry, these labels won't translate or follow language switches. Fix during the already-planned localization pass: route through `TranslateUi` + a retranslate hook, matching siblings.

## Improvements (smallest valuable first)

1. **Hold-to-compare / keyboard shortcut for Show original.** Today verifying a number requires hunting a checkbox in Advanced. A momentary key (hold) plus the existing checkbox is the highest-value usability change per line of code.
2. **Fail closed on rotated text.** `OcrResult.TextAngle` is never read ([uct_windows_ocr.cpp:163](/C:/Users/USER/AppData/Local/OkuFlow/worktrees/test-opt/src/common/uct_windows_ocr.cpp:163)). Rejecting lines when |angle| > ~2° prevents horizontal glyphs over tilted print instead of misregistering them; full rotation rendering stays deferred as documented.
3. **Cache per-word paint data.** Each paint does 6 `findChild` traversals, 2 `ReadableColors` (3 `pow` calls), and 2 hash ink lookups per word ([overlay.cpp:297](/C:/Users/USER/AppData/Local/OkuFlow/worktrees/test-opt/src/ui/ultra_clear_text_overlay.cpp:297), [overlay.cpp:339](/C:/Users/USER/AppData/Local/OkuFlow/worktrees/test-opt/src/ui/ultra_clear_text_overlay.cpp:339)). Precompute colors/scales and excluded-panel pointers in `SetWords`. Dense-page (200+ word) paint cost is currently unmeasured — the 2.8 ms fixture figure is ~15 words.
4. **Velocity-aware freshness:** when consecutive probe offsets differ by >~2 probe px, shorten the 350 ms window so fast motion hides sooner instead of swimming. Keeps fail-closed semantics.
5. **Status honesty:** "Showing sharp text for N words" counts `overlayWords_` including words the <6 px cutoff or panel clipping never draw ([ultra_clear_text_controller.cpp:548](/C:/Users/USER/AppData/Local/OkuFlow/worktrees/test-opt/src/app/ultra_clear_text_controller.cpp:548)). Count actually-projected words, or drop the number.

## Untested limits (not defects)

Real Windows OCR box-height semantics are unverified: the baseline fit is validated against tight-ink synthetic boxes, while `MakePage` uses uniform ascent+descent boxes, and the real-backend test only checks word centres within ±12 px. Parent should record actual `BoundingRect` heights for a mixed line (`of Changing page`) before trusting single-word-line sizing. Multi-column reading order interleaves columns (global left-to-right row sort); RTL order, rotated/perspective baselines, isoluminant colour text (grayscale OCR input), NVDA/Narrator behaviour, multi-monitor DPI moves, DWM/swapchain tear, and any CER/WER or real-camera acceptance remain unmeasured, consistent with `docs/ultra_clear_text.md`. No licensing concern found: OCR is Windows-inbox via SDK headers/`windowsapp.lib`, nothing redistributed.
