## P2-R1 — the new runtime recognizer bypasses BF16 plan/context size checks

**Location:** `src/common/uct_tensorrt.cpp:993–994` selects `PreparePinned`; its cold-build path at **563–587** deserializes, hashes and publishes the serialized plan without checking its length. Its context allocation at **637** also precedes the BF16 profile/output checks at **641–656**, and has no device-memory-size preflight.

**Source trace / conditional reproduction (not executed):** an eligible pinned BF16 graph builds a non-null serialized plan with payload size `P` such that `P + 32 >= 256 MiB`. The cold path can deserialize it, write `[32-byte SHA256][P-byte plan]`, pass its tensor smoke and become ready. On the next launch the same path's cache reader at **502–503** rejects that file by size, then rebuilds it. The immutable destination at **586–587** cannot be replaced. Separately, a compatible engine whose declared context memory exceeds 256 MiB reaches `createExecutionContext` directly; an allocation/API failure retires the entire GPU candidate instead of becoming a pre-allocation technical refusal eligible for selected-tier FP32.

The historical BF16 preparation checks serialized size before deserialization at **381–382**, and context size before context allocation at **415–418**. `d938b9a` routes normal recognizer startup around those guards, although only word-quality requirements were removed. The existing output-buffer limit remains in `Run`; workspace is also still limited. Those do not limit serialized bytes or context allocation.

**Fix:** make the runtime BF16 path validate serialized bytes before deserialization/publication, with a bound consistent with its actual digest-prefixed cache reader. Check the declared context memory and BF16 tensor/profile contract before allocating the execution context. Preserve the existing technical context ceiling, or explicitly define any intended capacity-specific resource ceiling; retain typed healthy-stream refusal plus confirmed drain for FP32 fallback. Do not introduce text, equality, corpus or accuracy checks.

**Confidence/limit:** the missing guards and cold/warm mismatch are source facts. I did not inspect actual plans or measure context sizes; this is not evidence that any current tier/device exceeds a ceiling. The generic helper predates this change for FP32/detector; the newly introduced exposure is normal BF16 recognizer admission through that helper.
