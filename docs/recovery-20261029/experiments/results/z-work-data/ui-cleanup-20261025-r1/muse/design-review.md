Sources read include `AGENTS.md`, `docs/ui_modes_design.md`, `docs/accessible_video_implementation.md`, `docs/ultra_clear_text.md`, `docs/localization.md`, `src/ui/main_window.cpp`, `src/ui/ultra_clear_text_panel.cpp`, `src/ui/video_transport.cpp`, `src/app/settings_store.cpp`, `settings_controller.cpp`, `ui_state_manager.cpp`, `app_settings.cpp`, `app_controls.cpp`, `app_video_playback.cpp`, plus the three owner PNGs (viewed directly, not inferred from names).

**Top finding:** the nine-tile grid misleads. Only one built-in (`preset-document`) turns on Text Clarity; “Keep It Steady” never enables stabilization; “Describe the Scene” silently starts periodic VLM analysis; and every preset switch overwrites the user’s reading colors. Fix the three screenshot defects and diet the grid to four task modes. Nothing below blocks safe implementation; defaults are given for each open detail.

## 1. UCT panel — move diagnostics under the disclosure, keep one status line out

In `UltraClearTextPanel::UltraClearTextPanel()` (`src/ui/ultra_clear_text_panel.cpp`) the layout is: enable checkbox, *Show original*, the `uctAdvancedSettings` toggle whose `modelControls` holds only the four `WheelSafeComboBox` tier selectors, then `backendLabel_` (`SetBackendStatus()` → “Using GPU backend: PaddleOCR / TensorRT CUDA”), `statusLabel_` (`SetStatus()` via `SetLiveText`), and the *Recognized text* `QPlainTextEdit` (96–220 px, `SetReadingText()` with caret remapping). The screenshot shows exactly this: the collapsed disclosure followed by three always-visible blocks inside Advanced → Image → Text clarity (panel added at `main_window.cpp:1092`, beside the separate collapsed *Fine-tune text* section). That is why the Image tab feels endless.

Do what the owner asked, with one amendment. Move `backendLabel_` and the reading pane (with its buddy label) **into** the disclosure content, below the tier selectors. Keep `statusLabel_` as a single compact line directly under *Show original*, above the disclosure header. Rationale: the backend string is developer diagnostics (tier names, TensorRT) and the pane is a large optional transcript; both belong behind progressive disclosure. Status (“Showing sharp text for 12 words”, “Waiting for steady text…”) is the only glanceable answer to “is it working?” and is the polite live region; hiding it risks suppressing the UIA event and forces an extra click to diagnose a blank overlay. If the owner insists on the literal placement, move status inside too but add an offscreen test proving `SetLiveText` announcements still fire while hidden — do not assume it.

Preserve contracts: keep object names (`ultraClearTextBackend/Status/ReadingPane`, `uctGpuDetector`…), buddies, focusability, and `UpdateDependentState()` visibility (`textClarityEnabled && checked`). Hidden pane/widgets must leave the Tab chain (Qt hidden widgets already do). Positioned screen-reader text is a separate viewport group (`uct_screen_text_accessible.cpp`), so hiding the pane does not remove UIA words — state this in the test, don’t just assert widget visibility. Do not change tier defaults (GPU medium/medium batch 8, CPU tiny/small in `uct_model_settings.hpp`), BF16/fallback, or the one-worker policy. Shorten the backend’s visible text inside the disclosure to plain language (e.g. “Graphics card” / “Processor”) only if it reuses existing catalog keys; otherwise keep the string and rely on hiding — any new UCT string still needs the 24-catalog small-agent review in `docs/localization.md`.

## 2. Playback volume — vertical popover, precise state machine

Today `VideoTransport` builds a permanent full-width `videoAudioRow` with horizontal `videoVolumeSlider` (0–100, step 5, page 10) plus a separate `videoMuteButton` in the main row (`video_transport.cpp` ctor, `UpdateActions()`, `FocusTargets()`: … mute → volume → Return). The screenshot’s second blue track at 16% permanently steals image height. Gain and mute are already independent in the app (`app_video_playback.cpp`: `doc.volumePercent` → `VideoAudioOutput::SetVolumePercent` PCM attenuation; `doc.muted` → `VideoPlayback::SetMuted`; `outputMuted` forces silence for Recording/Recap/active capture). The popover is a presentation change only; keep `MutedChanged`/`VolumeChanged` signals and the `Source::Video && hasAudio` gate.

Implement the settled interaction literally:

- Speaker stays a ≥44 DIP button (`kButtonExtent`). Popover is a frameless tool window like `modeGridPopup_`, anchored **above** the speaker, clamped to the viewport (flip only if above does not fit), ~64 DIP wide × ~150 DIP tall, containing a vertical slider (top = 100) and the existing `%` readout (`RefreshVolumeText()`). It overlays image temporarily and never changes transport layout height.
- Click 1 (closed) opens only — never toggles mute, even when muted. Click 2 (open) toggles mute **and closes**. Closing otherwise is Escape, outside click, Tab/Shift+Tab leaving, collapse/hide, or source change — none of which changes volume/mute. Say so in the speaker’s accessible description (“Press again to mute. Escape closes.”) reusing existing “Mute/Unmute playback” keys.
- Unify silence: dragging to 0 emits mute; dragging above 0 while muted unmutes to the dragged value. Keep session-only `lastNonzeroVolume` in `VideoTransport` (update on every emitted value > 0; seed from the first nonzero snapshot, else 100 to match current fresh-file `muted + 100%`). Unmute restores `lastNonzero`, never 0. While muted the slider still shows the stored gain with the slashed amber face (`ApplyFace()` / `SlashedIcon()` / `WarningTextColor` — already correct; audible = theme ink), and the readout reads e.g. “45%” with muted conveyed by name, not “0%”. This avoids the current two-silences trap (gain 0 with `muted=false`).
- Keyboard: Space/Enter on speaker opens and focuses the slider; Up/Down 5, PageUp/Down 10, Home/End limits (unchanged steps); `M` on the slider toggles mute without closing (for adjustment-then-mute checks); Escape closes and returns focus to the speaker; Tab from slider closes and continues to *Return to camera* (no focus trap). Reuse `MoveFocusFrom()`/`ReturnFocus()` and include the slider in `FocusTargets()` only while open.
- Speech: speaker name reflects state+value (“Mute playback” when audible is today’s action-name style — keep it, but set description to “Playback volume: 45%” via `SetLiveText` sync; when muted, “Unmute playback”). Slider keeps name “Playback volume”, description = locale `%`. Announce mute/unmute once, politely, deduplicated like `AnnounceSettledState()`; slider drags stay silent (value interface only). Guard `SetSnapshot`/`RefreshText` with the existing `!isSliderDown()` blocker so polling never yanks an active drag. Ignore wheel unless the popover is open and focused.

Edge cases: silent/Recording/Recap files show no speaker at all; opening a new file starts muted (existing safety) with popover closed; collapsing the transport closes the popover first and parks focus on the collapse chevron. Update `video_transport_tests.cpp::playbackVolumeIsAccessibleAndIndependentOfMuteAndSeek` — it currently asserts a visible horizontal slider — to cover open/close, second-click mute, drag-to-zero, last-nonzero restore, Escape focus return, and hidden-when-silent.

## 3. Quick modes — four tasks, no one-action commands, no destructive migration

Built-ins live in `settings_store.cpp::BuiltInConfigsStorage/BuiltInPresetsStorage` (10 configs; grid order = storage order; `kSimpleShortcutCount = 9` numbers rows 0–8 in `main_window.cpp`, plain labels via `PlainPresetLabel()`). Audited values (all `zoomEnabled`, centered; unlisted fields = `AdvancedConfig` defaults):

| Plain label (ID) | What it actually sets | Verdict |
|---|---|---|
| Read a Page (`preset-reading`) | zoom 1.6, temporal .25, spatial .25; Text Clarity **off** | Weak duplicate of Document |
| High Contrast (`preset-high-contrast`) | B&W threshold .62, zoom 1.5, temporal .18; **no** display colors/contrast change | Name promises colors it doesn’t set |
| Keep It Steady (`preset-steady-text`) | zoom 1.45, temporal .45; `stabilizationEnabled` stays **false** (`MakeConfig` predates the field) | Misleading — does not stabilize |
| Sharpen Text (`preset-sharp-text`) | zoom 1.55, spatial .45, temporal off | Subset of Document/Whiteboard |
| Zoom In More (`preset-large-zoom`) | zoom 2.3 + focus marker only | One-action view change, not a mode |
| See in Low Light (`preset-low-light`) | zoom 1.35, blur σ1.6, temporal .35; no brightness/auto-contrast | Softens text; doesn’t brighten |
| Describe the Scene (`preset-scene-explain`) | zoom 1.25, temporal .22, `vlmAssistEnabled=true` → `AssistiveFeatureManager::SetModes` periodic analysis | One-action Explain + hidden inference |
| Projector Screen (`preset-projector`) | zoom 1.4, temporal .25, keystone, auto-contrast .7, stabilization | Real task mode — keep |
| Whiteboard (`preset-whiteboard`) | zoom 1.5, spatial .35, keystone, auto-contrast .85, stabilization | Real task mode — keep |
| Document (`preset-document`, unnumbered 10th) | zoom 1.6 + full Text Clarity stack (`autoTextClarity`, flatten, Sauvola, smart-sharpen, two-color, hysteresis, glare…) | Only true reading mode — promote |

Three systemic problems: (a) every apply (`UIStateManager::ApplyConfigToUI`) overwrites `colorScheme/contrast/brightness` with preset defaults, so switching modes silently wipes a low-vision user’s saved reading colors — never bake colors into new modes and flag a follow-up to preserve current colors on apply; (b) baked zoom (1.25–2.3×) jumps on every switch even though pan/zoom is view navigation that deliberately does not reclassify the mode (`docs/ui_modes_design.md`); (c) on the CPU/raw path (“GPU Required — showing raw video”, `app_interaction.cpp`; selected-video CPU retains only zoom/rotation/colors/UCT) most preset effects are inert, and on media `vlmAssist`/debug are camera-only (`UpdateControlEnabledStates`). No preset enables SuperRes or UCT — keep it that way (UCT is a global `PersistentSettings` opt-in gated by Text Clarity, not a profile field).

**Front four (reuse IDs and existing translated labels, no new strings):**

1. **Read a Page → `preset-document`** (config as-is). Map `Document` to the existing “Read a Page” plain label. This is the desk/handout task and the only mode consistent with the Simple *Text Clarity* switch showing On.
2. **Projector Screen → `preset-projector`** (as-is) — distant static slides at an angle.
3. **Whiteboard → `preset-whiteboard`** (as-is) — handwriting/motion (sharpen, no temporal ghosting). Keep both screen modes: their temporal/sharpen difference is the one distinction users can feel.
4. **Keep It Steady → `preset-steady-text` + one-line fix** `stabilizationEnabled = true` (post-`MakeConfig`, like Projector). Without it the tile is false advertising. Note: exact-match owners become “Custom Setup” until they reselect — acceptable bug-fix fallout; their saved `currentConfig` pixels/settings are untouched.

Hide, don’t delete, the other six (`preset-reading`, `-high-contrast`, `-sharp-text`, `-large-zoom`, `-low-light`, `-scene-explain`): keep them in `BuiltInPresets()` so `FindPresetById/ResolveConfigForPreset/MatchPreset`, saved `selectedPresetId`s, custom presets, and the agent `mode.list/mode.activate` surface (`app_control_target.cpp`, incl. its `low_light → preset-low-light` goal) keep resolving. Filter only the Simple grid population (`PopulatePresetList` / `presetList_`): core four in task order, then customs, then — if the current selection is a hidden legacy — that one tile appended so the owner is never stranded. Numbers become 1–4 (+ customs); `UpdateCurrentPresetUi` badge/“Number key N” text follows automatically, but call out the renumbering in the changelog. *Zoom In More* and *Describe the Scene* leave the grid because wheel/Zoom slider and the *Explain* action (`ApplyExplainBusyUi`, bottom-right) already do those jobs as commands; periodic Scene Explain remains an explicit Advanced → Assistant behavior switch, never a preset side effect and never on at startup.

New-install defaults (existing files untouched): point `DefaultPresetId()` (only consumed by `SettingsController::InitializeDefaults` on missing settings) at `preset-document` so first run matches the “Read a Page” promise, and make *Reset Mode* (`ResetCurrentConfigToDefaults`, currently bare `AdvancedConfig{}`) resolve that same default — one meaning of “defaults”. Keep everything else: Simple mode, UCT off, `system` language, Fill, Auto ≤120 FPS, 5-min recap, inspector 520 DIP, and current section disclosure (Zoom/Colors/Text clarity/Camera/Language expanded; rest collapsed).
