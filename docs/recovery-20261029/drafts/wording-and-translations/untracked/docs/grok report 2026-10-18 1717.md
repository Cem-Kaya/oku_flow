# Grok report — 2026-10-18 17:17

Read of the current OkuFlow source. No camera, phone, or frame-time profile was run. Copy and slider costs below come from the call path, not a measurement.

## Live frame path

```
Capture (worker) → Ingress (mutex + deque) → Qt tick (UI thread)
    → CUDA (private stream) → D3D12 (graphics queue)
```

| Stage | What it does |
| --- | --- |
| Capture | Webcam via Media Foundation, or phone H.264 over USB. |
| Ingress | Preview keeps the newest frame. Recording holds six, then drops the burst. |
| Qt tick | One camera frame per turn. Pan and zoom redraw the cached scene. |
| CUDA | Convert, stabilize, grade, and sharpen into a shared texture. |
| D3D12 | Samples that texture. Zoom is applied here, not inside the effects. |

Side paths:

- **Recording.** Own GPU canvases. Original and processed stay paired. Pool pressure skips a frame.
- **Ultra Clear Text.** GPU snapshot is taken before zoom and color. CPU uses the pre-zoom scene.
- **Assistant.** Viewport readback is asynchronous. The image is copied before encode.

The steady NVIDIA path is the right shape for a magnifier. Media Foundation or the phone produces a frame, the UI thread runs effects once into a shared texture, and Direct3D 12 only samples that texture. Zoom, pan, and fit stay in the presenter, so a drag does not rerun stabilization or text enhancement. Recording uses its own GPU canvases, and a full pool skips a frame instead of stalling the view.

## What to change first

| Priority | Where | Issue |
| --- | --- | --- |
| P1 | Phone adb launch | The owned server starts the first `adb.exe` it finds. That binary is not hash-checked. |
| P1 | Android video queue | A full video queue closes the USB session. Metadata packets already drop instead. |
| P1 | Wedged camera | A stuck `ReadSample` is detected. Recovery still ends in an app restart. |
| P2 | Compatibility capture | Each frame is copied in system memory, then copied again into pinned GPU upload memory. |
| P2 | CPU present | Nearest-neighbor zoom walks every output pixel on the UI thread. |
| P2 | Slider drags | Each tick rematches presets and invalidates Super Resolution and text recognition. |
| P2 | App object | One executable and one `QObject` own camera, effects, UI, and the assistant. |

## Reliability

### The owned phone server can start an unchecked `adb.exe`

`FindAdbExecutable()` in `src/capture/phone_camera.cpp` returns the first file that exists: `OKUFLOW_ADB_PATH`, the bundled `platform-tools\adb.exe`, then `ANDROID_HOME`, `PATH`, and `%LOCALAPPDATA%\Android\Sdk`. `CreateOwnedAdbServer()` then launches that path as `adb -L tcp:<port> server nodaemon`. The legacy reclaim path checks a reviewed hash. The launch path checks only that the file exists. If the bundle is missing, or the environment variable points elsewhere, the app starts whatever binary it found and can send it device commands.

Spawn only the bundled binary after the same hash check, and treat an SDK or `PATH` copy as borrow-only.

### A stalled phone video queue ends the session

`UsbSocketServer.metadata()` already drops advisory packets when the control queue is full. `frame()` does the opposite: if the video queue (32 packets, 32 MB) rejects one frame, it calls `disconnect()` on that socket and clears the session. One USB pause therefore drops the camera, the control channel, and the torch together.

Drop or coalesce video under pressure, and disconnect only on a write timeout or a dead socket.

### A wedged webcam is detected, then the process is stuck with it

`ConsumeDeviceLost()` times out an in-flight `ReadSample` (10 seconds, or four frame periods, capped at 60) and sets `running_` to false. That flag does not unblock the driver call. `Quiesce()` later calls `Flush` and `join` on a detached stop thread. If the driver ignores `Flush`, `PollStopCapture()` abandons the session after 1.5 seconds and the UI says to restart. The blocked thread, reader, and D3D11 device stay alive until the process exits, and another camera cannot open. The UI no longer hangs, which is the important part. The missing piece is a way to abandon that reader without a full process restart, or a watchdog that can cancel the read itself.

## Performance

### Compatibility capture copies the frame twice on the UI thread

The zero-copy rung keeps the camera texture on the GPU. The fallback first packs the Media Foundation buffer into a `vector` in `CopyCaptureBuffer()`, then `copyRows()` memcpy’s it into pinned memory inside `ProcessFrame` before the async upload. At 1080p NV12 that is roughly 3 MB of CPU traffic per frame, on the same thread that draws the window.

Keep the accelerated rung, and move the pinned pack off the UI thread when the GPU texture cannot be used.

### The CPU presenter is a nearest-neighbor loop

`PresentFitted()` zeroes `presentationBuffer_` and then, for every output pixel, rounds a source coordinate and copies four bytes. That is the path when CUDA is unavailable or the debug composite is on. It blocks the UI for the whole viewport, and the magnified image is blocky. A small shader or a stretched D3D upload would do both jobs better. The GPU path already does this: `PresentSceneTexture()` draws a triangle and samples the shared texture.

### With a shared fence, the UI does not wait for CUDA

`ProcessFrame` signals the imported D3D12 fence and returns. `PresentSceneTexture` waits for that value on the graphics queue. The `SynchronizeStream()` loop, which sleeps 1 ms for up to a second, runs only when that semaphore is absent. Same for `WaitForIdle()` after a recording clone. If a machine logs “CUDA surface ready without fence interop,” every frame pays that drain. Treat a failed fence import as a startup failure you can see, rather than a silent slower mode.

### Slider motion does too much per tick

`OnBlurSigmaChanged` and the other value handlers call `SyncCurrentConfigToPersistence()`. That bumps `cudaProcessingGeneration_`, calls `InvalidateSuperResRequest()`, notifies the agent surface, rereads every control through `ReadConfigFromUI()`, and walks the preset list to rematch. It does not write `settings.json` on each tick. It does throw away an in-flight Super Resolution result and an Ultra Clear Text generation while the user is still dragging.

Coalesce that invalidation until the slider is released, and rematch the preset on a short timer.

### Ink on a recording is painted on the UI thread

When the overlay has strokes, each recorded frame allocates a full-canvas `QImage`, fills it, and strokes it before `RequestRecordingFrame`. Move that raster to the recording worker, or cache it until the strokes change.

## Structure

`cmake/CMakeLists.txt` globs every `src/*.cpp` except the launcher and MCP into one `oku_flow` executable. Module folders are a convention. `OkuFlowApp` is the composition root: it holds the camera session, the CUDA surface, the presenter, recording, the assistant, and one slot per slider (`app.hpp` from `OnBlackWhiteToggled` through the text-clarity members around line 486). `MainWindow` is the matching UI object. Image settings also live in the widgets and in `settings::AdvancedConfig`, and `CaptureCurrentAdvancedConfig()` trusts the widgets.

Splitting this into `okuflow_capture`, `okuflow_cuda`, `okuflow_d3d12`, and `okuflow_ui` libraries would make the boundary real and would let tests link one module. After that, replace the loose scalars with one live `AdvancedConfig` and bind the widgets to it. Do the build split first. It does not change behavior.

## Intentional, not defects

- Extra Stable (`bumpHold`) is marked `session_only` with “no saved field” in `parameter_registry.cpp`, and `OnBumpHoldToggled` skips persistence because the hold can freeze moving content.
- The six-frame recording queue wiping itself on overflow is what `captureBurstKeepsJitterAndCatchesUpOnOverflow` asserts: the recorder jumps to the newest frame instead of staying six frames behind.
